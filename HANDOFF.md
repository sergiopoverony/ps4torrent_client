# PS4 Torrent Client (remote) — сводка для продолжения в новом чате

Вставь этот файл первым сообщением в новый чат и прикрепи `ps4tc_client_src.zip`
(или отдельные файлы из него) — тогда Claude сразу поймёт контекст и сможет
править код, а не писать заново.

## Что это за проект

Экранное PS4-приложение (`.pkg`, homebrew, тулчейн **OpenOrbis**, прошивка 13.02,
джейлбрейк GoldHEN), которое **ничего не качает само**. Оно только:
- опрашивает `ps4torrentd` (отдельный демон, управляет BitTorrent-загрузками,
  работает в фоне, запущен на той же консоли через GoldHEN BinLoader) по HTTP,
  `127.0.0.1:8787`;
- рисует таблицу раздач на телевизоре (как в игровом UI, не браузер);
- управляется геймпадом: пауза/продолжить, удаление с подтверждением.

У пользователя уже отдельно, в другом чате, написан и работает сам `ps4torrentd`
(исходники мне присылались как `ps4torrentd-src.zip`, в этом чате их нет — если
понадобится свериться с сервером, попроси пользователя прислать заново).

**ВАЖНО, НЕ ПУТАТЬ С ПРЕДЫДУЩИМ ПРОЕКТОМ**: до этого в другом чате пытались
сделать полноценный самодельный BitTorrent-клиент с экраном (без внешнего
демона) — там были проблемы с песочницей (USB недоступен, установка PKG через
системные библиотеки падает и т.д.). От этого подхода отказались. Текущий
проект — это **только лёгкий HTTP-клиент**, никакой работы с протоколом
BitTorrent, файловой системой USB или установкой PKG внутри него нет и не
должно быть — всё это делает `ps4torrentd` сам, в обход песочницы (так как
работает как payload через BinLoader, а не как `.pkg`).

**Принципиальное ограничение, которое нужно соблюдать и дальше**: не предлагать
и не встраивать в этот `.pkg`-клиент код для обхода песочницы, kernel read/write
или что-то подобное — даже если попросят, даже со ссылкой на готовые чужие
библиотеки. Этот клиент — обычное userland PS4-приложение, работающее строго
через HTTP к уже существующему демону, и должен оставаться таким.

## Протокол ps4torrentd (проверено по исходникам сервера, не по README)

HTTP/1.0, сервер закрывает соединение после каждого ответа (`Connection: close`
можно не отправлять, но мы отправляем для порядка), всегда есть
`Content-Length`. Порт веб-сервера **зашит константой `HTTP_PORT 8787`** в
исходниках сервера — это НЕ то же самое, что поле `listen_port` в JSON (это
порт для входящих BitTorrent-соединений, обычно 6881, другая сущность).

### `GET /status` — ответ:
```json
{
  "items": [
    {
      "hash": "40-символьный hex", "status": "queued|checking|downloading|paused|complete|offline|waiting",
      "size": 0, "done": 0, "pct": 0, "speed_kb": 0, "eta_s": -1, "peers": 0,
      "paused": false, "low_space": false, "root": "/mnt/usb0/torrents", "title": "..."
    }
  ],
  "drives": [
    { "root": "...", "free": 0, "total": 0, "kind": "internal|usb", "low": false }
  ],
  "speed_kb": 0, "max_parallel": 3, "listen_port": 6881, "incoming": 0,
  "deleting": 0, "net_ip": "192.168.0.24", "net_restarts": 0, "net_heals": 0,
  "version": "1.0"
}
```
`net_ip` — это LAN-адрес консоли (тот, что сервер сам пишет в уведомлении
`"ps4torrent web: http://%s:%d/"`); если интернета/сети нет, пусто или
`127.0.0.1`.

### Команды (все `GET`, ответ `{"ok":true}` или `{"ok":false,"error":"..."}`):
- `/api/pause?hash=...`
- `/api/resume?hash=...`
- `/api/pause_all`, `/api/resume_all`
- `/api/delete?hash=...` — убрать из списка, файлы остаются
- `/api/delete?hash=...&files=1` — убрать и стереть скачанные файлы
- `/api/config` — настройки сервера (не используется клиентом сейчас)

Опциональный `token`: если у сервера задан пароль, добавляется `&token=...` ко
всем путям, кроме `/`. В клиенте это уже реализовано (`g_token`, необязательный
файл `/data/ps4tc_client/config.txt`).

## Файлы клиента (все в zip `ps4tc_client_src.zip`, папка `ps4tc_client/`)

- `main.cpp` — точка входа: `net_init()`, `ui_init()`, цикл `ui_pump()`.
  Читает необязательный `/data/ps4tc_client/config.txt` (`host=`, `port=`,
  `token=`; по умолчанию `127.0.0.1:8787`, без пароля).
- `app.h` — структуры `Item`, `Drive`, `ServerStatus`; глобали `g_status`,
  `g_host`, `g_port`, `g_token`.
- `api.h/cpp` — обёртка над HTTP API: `api_refresh_status()`,
  `api_pause/resume/delete()`, разбор JSON в `g_status`. **Проверено
  по-настоящему**: поднимался локальный Python HTTP-сервер, повторяющий точный
  протокол `ps4torrentd`, и через него гонялся реальный код (не моки).
- `httpc.h/cpp` — минимальный HTTP/1.0-клиент поверх `net.cpp` (GET/POST).
- `json.h/cpp` — свой разборщик JSON (не универсальная библиотека, под формат
  ответов сервера). Проверен на реальном формате `build_snapshot()` сервера:
  кириллица, экранированные кавычки, `\u`-escape, пропущенные поля, битый JSON.
- `net.h/cpp` — сокеты, тот же код, что и в `ps4torrentd` (сверено, идентичен).
- `scene.h/cpp` — PS4 video out + FreeType, рисование прямоугольников/пикселей.
  Взят из более раннего рабочего проекта (уже проверялся на консоли там).
- `image.h/cpp` — загрузка PNG через `stb_image.h` (есть в тулчейне,
  `#include <stb/stb_image.h>`, не нужно ничего докачивать). Используется для
  баннера `title.png`. `#define STBI_ONLY_PNG` и т.п. — читай сам файл, там
  комментарии.
- `ui.h/cpp` — САМЫЙ ИЗМЕНЯЕМЫЙ ФАЙЛ. Таблица раздач, геймпад, диалог удаления,
  полоска прогресса, баннер, верхняя строка статуса. Подробности ниже.
- `connstate.h` — только заголовок: `conn_state()` решает, что писать в шапке (IP:port /
  NO INTERNET / NO PAYLOAD), с запасом времени `CONN_GRACE_US`. Проверено тестом по секундам.
- `log.h/cpp` — пишет в `/data/ps4tc_client/log.txt` (отдельно от лога
  `ps4torrentd`, не путать).

## Текущее состояние UI (ui.cpp) — важные детали, чтобы не наступить дважды

**Раскладка экрана** (1920×1080):
- Баннер (`title.png`, PNG, у пользователя 839×191) — верхний левый угол,
  `BANNER_LEFT=12` (прижат к краю по просьбе пользователя), высота на экране
  `BANNER_H=64`, ширина пересчитывается по пропорциям картинки
  (`g_bannerW = BANNER_H * img.width / img.height`). Если баннер не загрузился
  (нет файла в `/app0/assets/images/title.png` или ошибка декодирования) —
  пишется запасной текст, приложение не падает.
- Строка статуса справа от баннера, **один `draw_text()` вызов, один цвет**. Первый
  элемент строки показывает состояние связи, **три варианта** (решает чистая функция
  `conn_state()` в `connstate.h` — она покрыта тестом, не дублировать логику в `ui.cpp`):
  1. сервер отвечает на `127.0.0.1:8787` И есть настоящий внешний адрес (`net_ip` не пустой
     и не `127.0.0.1`) → `192.168.0.24:8787` (обычным цветом; жёлтым, если на каком-то диске
     `low == true`);
  2. сервер отвечает, но внешнего адреса нет (интернета нет) → `NO INTERNET` **жёлтым**;
  3. сервер не отвечает → `NO PAYLOAD` **красным**.
  - **Запас времени (10 с, `CONN_GRACE_US`)**: `NO PAYLOAD` появляется, только если успешного
    ответа не было дольше 10 секунд (или не было ни разу с запуска приложения — тогда сразу).
    Причина: при смене состояния сети `ps4torrentd` на несколько секунд пересоздаёт свой
    веб-сокет (он проверяет сеть раз в 5 с), и порт 8787 в эти моменты может не отвечать;
    без запаса шапка при отключении интернета мигала `NO PAYLOAD`, хотя payload жив. В течение
    запаса держится последнее известное состояние. Побочный эффект, озвучен пользователю:
    настоящая остановка payload показывается с задержкой около 10 с.
  - Время последнего успешного ответа хранится в `g_lastOkUs`; заполняется ТОЛЬКО через обёртку
    `refresh_status()` в `ui.cpp` (не вызывать `api_refresh_status()` напрямую из `ui.cpp`).
  - Диски/скорость/пиры показываются **во всех трёх случаях** по последним известным данным
    (`api_refresh_status()` не стирает `g_status` при неудаче, только ставит `ok=false`).
    Пока ни одного успешного ответа не было, эти поля нулевые/пустые — это нормально.
  - формат при полном порядке:
    `192.168.0.24:8787 | HDD: 20.1GB free | USB: 4.5GB free | 1.5MB/s | 3 peers | 3 parallel`
  - `HDD:` для внутреннего диска (`kind == "internal"`), `USB:` для остальных.
  - Числа ГБ **вплотную к единице**: `fmt_size()` для диапазона GB даёт `"%.1fGB"` без
    пробела (например `20.1GB`) — функция общая, так что это же видно и в колонках Size/Done.
- Заголовок таблицы на английском: `Title | Size | Done | ETA | Status | Peers`. Колонка **ETA**
  (между Done и Status) показывает оставшееся время (`23m`, `1h23m`, `2d`) только для статуса
  `downloading`, иначе тусклый `-`. Под неё Title сужен с 56 до 46 символов; позиции Status
  (колонка 94) и Peers (109) не менялись. Между колонками везде зазор ровно 2 символа,
  всего 115 символов (запас по ширине экрана нулевой — новую колонку можно добавить только
  за счёт сужения другой).
- Полоска прогресса под каждой строкой: высота строки увеличена с 34 до 40px
  (`ROW_H=40`, добавлены `BAR_H=4`, `BAR_GAP=4`), полоска шириной от начала
  колонки Title до правого края колонки Status (Peers НЕ включён), серая
  "дорожка" (`C_TRACK` {55,59,68}) + **голубая** заливка (`C_FILL` {81,171,236}) по `it.pct`.
  `C_GREEN` для заливки НЕ используется (он остаётся для статуса `complete`).
- Выделенная строка: **серая в тон синему** (`C_SEL` {72,82,96}, оттенок 215°, тот же, что был у прежнего
  синего {38,88,160}). Эти два цвета пользователь выбирал сам, потом они "потерялись" и были возвращены —
  не менять без просьбы. Из-за увеличения
  `ROW_H` видимых строк в таблице стало **21 вместо 25** — это сознательный
  компромисс, озвучен пользователю.
- Статусы в таблице — английские слова: `checking / downloading / paused /
  complete / drive gone (было offline) / waiting / queued`.
- Низ экрана, ДВЕ строки по центру (была проблема с наложением — исправлено,
  см. константы `HINT_BASELINE`/`CREDIT_BASELINE` с зазором 32px):
  1. `Up/Down - select   Cross - pause/resume   Triangle - remove` (`C_DIM`)
  2. `ps4torrent client v1.5.2.3 Created by SergioPoverony and Mr.Claude`
     (`C_DIMMER`, тусклее первой строки). **Версию и текст менять ровно по
     просьбе пользователя, не придумывать своё.**
- Диалог удаления (текст **дословно** взят из веб-страницы `ps4torrentd`, не
  придумывать заново): заголовок `Remove this torrent?`, кнопки
  `[Cross] remove   [Square] remove + files   [Circle] cancel`.

## Параметры сборки (Makefile), на момент паузы

```
TITLE       := PS4 Torrent Client
TITLE_ID    := BREW00088
CONTENT_ID  := IV0000-BREW00088_00-PS4TC00000000000   (ровно 36 символов! это важно, раз уже ловили ошибку PkgTool "Content ID must be 36 characters long")
LIBS        := -lc -lkernel -lc++ -lSceNet -lSceVideoOut -lSceSysmodule -lSceFreeType -lScePad -lSceUserService
EXTRAFLAGS  := -O2
```
`--paid` должен быть `0x3800000000000011` (обычный homebrew, НЕ `...0010` —
та особая подпись была нужна только для экспериментов с системным
установщиком PKG в ДРУГОМ, более раннем проекте, тут не нужна).

**Частые грабли с этим Makefile** (уже не раз наступали в соседнем проекте,
возможно будет и тут): иногда в файле оказываются ДВЕ строки `LIBS :=` —
проверять `Select-String -Path Makefile -Pattern "LIBS"` перед тем как гадать,
почему линковщик не видит библиотеку. Опечатка `:=- lc` (пробел не в том
месте) тоже уже встречалась — должно быть `:= -lc`.

## Что НЕ проверено на реальной консоли

**Вообще ничего из этого клиента ещё не запускалось на PS4.** Пользователь
собирает и тестирует пошагово, последняя просьба была про поведение при
пропадании интернета — она только что исправлена (см. выше), но
подтверждения от пользователя, что именно это исправление уже проверено на
железе, в истории чата нет на момент сохранения этой сводки. Нужно спросить
результат следующего теста.

Всё, что проверено — проверено у меня локально (без консоли): синтаксис
компиляции (под заглушки системных заголовков PS4), разбор JSON на реальном
формате сервера, HTTP-клиент через настоящий локальный сервер на Python,
математика смешения цветов/масштабирования картинки баннера, арифметика
раскладки экрана (что строки не накладываются, что всё помещается в 1080px).

## Стиль работы с пользователем

- Не программист, объяснять просто.
- Код — целыми файлами на замену, не патчами (пользователь копирует файл
  поверх в `C:\ps4dev\OpenOrbis\samples\ps4tc_client\ps4tc_client\`).
- Перед выдачей пользователю — самому тестировать код (заглушки системных
  вызовов, реальные мини-серверы для сетевого кода, санитайзеры где возможно).
- Общение на русском, интерфейс самого приложения — на английском (решение
  пользователя, см. выше).
- Если пользователь прислал README/исходники — сверяться с ними дословно
  (цитаты кнопок, текст футера и т.п.), не придумывать свою формулировку.
